## 漏洞与整改证据

| 风险 | 旧行为 / 证据 | 整改与验证 |
| --- | --- | --- |
| 高：身份冒领 | 学号、姓名匹配即可自助绑定；姓名错误时返回正确姓名。旧插件合成复现确认普通用户进入写接口 | 普通用户的私聊文字或文件名仅生成待审核申请；后端拒绝未批准绑定，错误不返回花名册姓名；角色仅由可信平台事件核验 |
| 高：群聊数据泄露 | 管理员可将全班归档发入群文件；旧动作合成复现确认调用 `upload_group_file` | 导出、查重、个人查询与名单入口限制为有权限的私聊；回归包含管理员群聊拒绝路径 |
| 高：凭据传播与异常泄密 | 全权限 key 放进导出 URL；异常文本直接回显。旧动作合成复现检出测试 token | 插件自行带请求头下载，只向 OneBot 发送本地副本；异常统一提示；后端拒绝 URL token，移除记录 URI 的通用访问日志，浏览器下载改用请求头 |
| 高：API 默认开放 | key 为空时跳过鉴权 | 所有 `/api/*` 始终启用鉴权，未配置返回 503；头部错误、缺失、URL token 均有拒绝测试 |
| 高：事件来源混淆 | 仅以发送者数字判断角色，监听器接受所有平台 | 新入口验证平台实例与机器人账号；其他实例使用管理员数字仍被拒绝 |
| 高：附件路径 / 网络边界 | SDK 返回路径可指向任意本地文件或远程 URL，插件会上传并删除该路径 | 拒绝 URL 和收件目录外路径；检查打开的文件实际路径、类型、大小，仅上传并清理插件副本；哨兵文件、符号链接和超限文件测试通过 |
| 高：邮件附件 SSRF | 主机名只检查包含 `qq.com`，并允许 localhost；下载响应中的 URL 和重定向未限制 | QQ HTTPS 域名边界校验、连接时固定已校验的公网 IP、重定向校验；环境代理关闭。合成 QQ 响应通过本地测试传输验证，不接触上游真实文件 |
| 高：规则文件越界写入 | 作业 ID 直接拼接为 YAML 路径 | ID 白名单、名单路径与符号链接范围检查、`os.Root` 文件写入；越界 ID 与外部符号链接写保护测试通过 |
| 中：确认流程权限过期 | 发布确认没有复核角色；旧代码复现先遇到正则 f-string `NameError`，未证明成功发布 | 确认时复核权限；同时修复字符串构造；覆盖撤权拒绝与管理员允许，不将旧版异常当成安全控制 |
| 中：并发绑定 | 删除旧绑定与写入新绑定分离 | 数据库同一写事务中完成替换；现有绑定测试与 race 检查通过 |
| 中：限流和数据保留 | 确定性命令未限流；统计永久保存原始账号、群标识 | 每用户及全局事件限流、每事件最多 8 次工具调用；统计 HMAC 假名化、30 天保留、0600 文件，旧记录需要独立受限归档 |
| 中：私有部署耦合 | 个人邮箱、班级规则、学号特判和测试中的实际身份样例 | 移除邮箱与学号特判，花名册决定班级；改用合成身份；新作业名单显式配置，端到端示例不再读取真实 data 目录 |

`force: true` 只表达管理客户端的批准意图；后端共享 API key 仍是全权限凭据，不能直接交给普通用户。原有绑定未自动删除或重新验证，管理员必须在上线前核查历史自助绑定。

## 本地验证

- `go test ./...`：通过；其中未跟踪的本地诊断命令仅编译，未运行其 main 函数。
- `go test -race ./internal/api ./internal/db ./internal/rule ./internal/parser`：通过。
- 插件 `python -m unittest discover -s tests -v`：20 项通过，包括身份申请的允许与拒绝路径、真实回环 HTTP 重定向测试；第二目标未收到凭据。
- 插件 `python -m compileall -q .` 与两仓库 `git diff --check`：通过。
- Python `pip-audit -r requirements.txt`：当前固定的 aiohttp 3.14.5 及解析依赖未发现已知漏洞；不代表 AstrBot/SnowLuma 镜像已审计。
- `govulncheck -json ./cmd/server`：在本机 Go 1.26.7 上发现 11 项标准库符号可达告警，修复版本为 **Go 1.26.9**。包含 GO-2026-6603 至 6613 中的适用项，以及 GO-2026-6617。另有 `golang.org/x/text` 模块级告警 GO-2026-5970、GO-2026-6629，未报告当前服务调用相应漏洞符号；修复版本分别为 0.39.0、0.41.0。
- 后续构建链整改：`go.mod` 的最低版本改为 1.26.9；Flake 对锁定 Nixpkgs 中的 Go 1.26.8 做项目内固定源码覆盖。`GOTOOLCHAIN=go1.26.9 go test ./...` 和 `nix build .#packages.x86_64-linux.default --no-link -L` 通过；`go version -m` 确认本地 Nix 二进制由 Go 1.26.9 编译。使用 Go 1.26.9 复扫 `./cmd/server` 后无标准库告警，只剩前述两项 `x/text` 模块级告警。

`go.sum`、`flake.lock` 和第三方依赖未变；不能把本地构建等同于运行中服务已升级。两项模块级告警需要随依赖维护单独复查。`govulncheck` 的符号可达结果是静态证据，并不证明漏洞已在现网被利用。Go 1.26.9 修复内容见 [官方发布记录](https://go.dev/doc/devel/release#go1.26.9)。

## 上线门槛与回退

1. 确认部署归属，固定 AstrBot、SnowLuma、后端与插件版本；在部署环境构建并核对 `go version -m` 为至少 Go 1.26.9，复跑漏洞审计。
2. 在无真实账号和课程数据的隔离环境验证框架调度、平台 ID、OneBot token、HTTPS、模型工具范围与用户/群会话隔离。
3. 配置收件目录与同路径共享传输目录，验证 OneBot 上传返回前完成读取。URL-only 适配器暂不支持，不能静默恢复任意 URL 下载。
4. 备份并人工复核现有绑定；保留运行时配置、旧统计和登录卷，不将其复制到新仓库。为统计使用新数据库或受控迁移，防止旧原始标识继续保留。
5. 更新浏览器、脚本和调用方到头部鉴权。反向代理禁止记录旧查询凭据，检查历史访问日志；插件本身无法清理代理与平台日志。
6. 首次部署只替换后端和插件，不重启或重建 QQ 登录容器。出现兼容性问题时停用课程插件、恢复原二进制/插件与受限配置备份。代码恢复点为 `b1df923`，但回退会恢复已知漏洞，旧版本须保持隔离。
